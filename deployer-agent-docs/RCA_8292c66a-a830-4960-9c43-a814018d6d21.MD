# RCA — Deploy failure (run 8292c66a-a830-4960-9c43-a814018d6d21)

## Summary
The redeploy failed at the `deploy_k8s` step: the FastAPI backend crash-looped on
startup, so `/health` never came up and the rollout timed out
("deployment failed to become ready"). The pod itself scheduled and the image ran —
this was an application boot crash, not an infra/manifest fault.

## Root cause (confirmed)
Backend boot crash in `backend/server.py` line 58:

```
RuntimeError: CORS_ORIGINS is not configured with explicit production origin(s).
```

The code (server.py:56-58) is intentional hardening:

```python
_cors = [o.strip() for o in os.environ.get("CORS_ORIGINS", "").split(",") if o.strip() and o.strip() != "*"]
if not _cors:
    raise RuntimeError("CORS_ORIGINS is not configured with explicit production origin(s).")
```

It drops empty entries and the wildcard `*`; if nothing explicit remains it refuses to start.
(This is also correct per the CORS spec — `allow_credentials=True` with `allow_origins=["*"]`
is invalid.)

The production secret store holds `CORS_ORIGINS = *` — verified via list_secrets
(`matches_expected: true` for value `*`, `is_empty: false`). The new code strips `*`,
the list is empty, and the process exits.

Why a normal redeploy will NOT fix it:
- Pre-existing deployment secret values are NOT overwritten on redeploy, so prod keeps `*`.
- The preview `backend/.env` only sets a PREVIEW origin
  (`CORS_ORIGINS="https://anjali-ayurveda-mvp.preview.emergentagent.com"`), which is not a
  production origin and would not be adopted for an already-existing prod key regardless.

## The fix (owner: user, via UI)
Update the `CORS_ORIGINS` secret in Deployment Panel -> Secrets to the explicit production
origins (comma-separated, no `*`), then redeploy:

```
CORS_ORIGINS=https://anjali-ayurveda-mvp.emergent.host,https://anjaliherbal.life,https://www.anjaliherbal.life
```

(origins taken from the deployed URL + the two verified custom domains on this deployment).

## Recommended follow-up (owner: E1, preview source) — optional
For preview/prod consistency, update `backend/.env` `CORS_ORIGINS` to include the real
production origins (not just the preview URL). This keeps the preview build aligned, but the
operative fix for the deployed app is the Secrets-UI update above, because the existing prod
secret value is not overwritten by a redeploy.
